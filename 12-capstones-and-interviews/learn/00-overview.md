# Stage 12 — Capstones: Overview

Stages 1–11 built skills in isolation. Capstones ask you to **ship something coherent**: a problem statement, working system, evaluation, and a story you can tell in a portfolio or interview.

You do not need a startup. You need a finished slice with honest limitations.

## Goals for Stage 12

By the end of Stage 12, you should be able to:

- Pick a project scoped to a few weeks with clear success criteria
- Choose from a catalog of ideas matched to skills you want to showcase
- Follow (or adapt) an end-to-end build guide for a Docs Q&A RAG system
- Follow (or adapt) an end-to-end build guide for a tabular ML + LLM hybrid report
- Package README, demos, and metrics for a portfolio
- Plan what to learn next without drowning in random tutorials

## Prerequisites

You should have completed **Stages 1–11** checklists (or equivalent experience). Especially:

- Classical ML workflows and metrics
- Comfort calling LLMs and validating outputs
- Awareness of RAG failure modes and production basics

## Suggested time

About **3–6 weeks** part-time for one solid capstone (longer if you attempt both major builds).

| Phase | Focus |
|-------|--------|
| Week 1 | Pick project; write proposal; gather data rights |
| Weeks 2–4 | Build MVP; evaluate; harden README |
| Weeks 5–6 | Polish demo; write postmortem; portfolio packaging |

## Success criteria for “done”

A capstone is done when:

- Someone else can run it from the README
- You report metrics on a held-out or golden set (not only cherry-picked demos)
- You document failures and next steps honestly
- You can explain architecture decisions in five minutes without slides

Ship depth over width. One excellent project beats five half-finished clones.
