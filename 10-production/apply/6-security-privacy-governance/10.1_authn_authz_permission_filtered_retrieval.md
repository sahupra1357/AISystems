# 10.1 Security → Authentication & authorization (permission-filtered retrieval)

> **Source:** `AI_System.md` §10 Security, privacy & governance
> **Pipeline stage:** every request
> **One-liner:** Retrieval must be permission-filtered *at query time* with the caller's identity, not filtered after generation. Multi-tenant isolation belongs in the index — tenant-scoped namespaces or mandatory filters — not in prompt instructions.

---

## What it is

The security model of a RAG system is simple to state and easy to get wrong: **the model must never receive a chunk the caller cannot see.** Everything else follows.

Three wrong approaches, in increasing order of how common they are:

| Anti-pattern | Why it fails |
|---|---|
| "Instruct the model not to reveal restricted content" | The model already has it in context; instructions are not access control, and injection defeats them (08.4) |
| Filter the *answer* after generation | The data already left the boundary; partial leakage through summaries and inferences |
| Post-filter the top-k results | For a user who can see 1% of the corpus, top-100 filtered can return zero — and the failure is silent (04.3.3) |

The correct approach: the caller's identity is resolved to a set of groups, and those groups become a **mandatory filter inside the vector search**, alongside tenant and current-version filters. The chunk carries its ACL from ingest (00.1.5); the query carries the caller's; the store intersects them.

```
request → authenticate → resolve caller → groups
                                  │
       ┌──────────────────────────┴──────────────────────────┐
       ▼                                                     ▼
tenant_id == caller.tenant  AND  acl_groups ∩ caller.groups ≠ ∅  AND  is_current
       │                                                     │
       └────────────── applied INSIDE the ANN search ────────┘
                                  │
                   only permitted chunks ever exist in the context
```

## How to implement

1. **Authenticate every request** and resolve to a caller object: user ID, tenant ID, group memberships, roles. Never accept identity from the request body or from model output.
2. **Resolve groups from the identity provider** with a short-TTL cache, and invalidate on revocation events where available.
3. **One filter-builder function** used by every retrieval path — dense, sparse, graph, memory, and any tool that reads documents. Never construct filters ad hoc.
4. **Apply inside the search** (04.3.3), never as post-processing. Verify the store does native filtered ANN.
5. **Re-check on fetch**: parent documents (04.1.5), page images (00.3.4), and citation links are separate reads that need their own authorisation.
6. **Deny by default**: missing or empty ACL means nobody, enforced at index write (00.1.5) and at query time.
7. **Non-disclosing refusals**: when the answer exists but the caller can't see it, the response must be indistinguishable from "nothing found" (04.7.5).

## Small example

```python
from dataclasses import dataclass
from functools import lru_cache

@dataclass(frozen=True)
class Caller:
    id: str; tenant_id: str; groups: frozenset[str]; roles: frozenset[str]
    def principal_set(self) -> set[str]:
        return set(self.groups) | {f"user:{self.id}", f"tenant:{self.tenant_id}:all"}

def authenticate(request) -> Caller:
    claims = verify_jwt(request.headers["Authorization"])          # signature + audience + expiry verified
    return Caller(id=claims["sub"], tenant_id=claims["tid"],
                  groups=frozenset(resolve_groups(claims["sub"])), roles=frozenset(claims.get("roles", [])))

@lru_cache(maxsize=10_000)
def _groups_cached(user_id: str, epoch: int) -> frozenset[str]:
    return frozenset(idp.get_group_memberships(user_id))            # short TTL via epoch bucketing

def resolve_groups(user_id: str, ttl_s: int = 120) -> frozenset[str]:
    return _groups_cached(user_id, int(time.time() // ttl_s))

# ---- THE single filter builder: every read path uses this ----
def build_acl_filter(caller: Caller, extra: dict | None = None) -> dict:
    principals = sorted(caller.principal_set())
    assert caller.tenant_id and principals, "refusing to build an unscoped filter"
    flt = {"must": [
        {"key": "tenant_id",  "match": {"value": caller.tenant_id}},
        {"key": "is_current", "match": {"value": True}},
        {"key": "acl_groups", "match": {"any": principals}},
    ]}
    if extra:
        flt["must"].extend(extra.get("must", []))                   # user-intent filters ANDed on top (04.4.5)
    return flt

def retrieve(query: str, caller: Caller, k=30, intent_filters=None):
    flt = build_acl_filter(caller, intent_filters)
    dense  = vec.search(embed_queries([query])[0], limit=k, query_filter=flt)     # inside the ANN search
    sparse = bm25.search(query, limit=k, filter=flt)                              # SAME filter, both legs (04.5.1)
    return rrf({"dense": [h.id for h in dense], "sparse": [h.id for h in sparse]})

# ---- authorisation on every subsequent read, not just the search ----
def fetch_parent(parent_id: str, caller: Caller) -> dict:
    p = parent_store.get(parent_id)
    if p["tenant_id"] != caller.tenant_id or not (set(p["acl_groups"]) & caller.principal_set()):
        audit_log("authz_denied", caller=caller.id, resource=parent_id)
        raise PermissionDenied(parent_id)                            # ACL drift between parent and child
    return p

def serve_page_image(doc_id: str, version: int, page: int, caller: Caller):
    if not document_readable_by(caller, doc_id, version):
        audit_log("authz_denied", caller=caller.id, resource=f"{doc_id}#p{page}")
        raise PermissionDenied(doc_id)                               # a citation link is a document link (00.3.4)
    return image_store.get(doc_id, version, page)

# ---- continuous cross-tenant canary ----
def cross_tenant_canary():
    """A synthetic doc in tenant A must never surface for a tenant B caller."""
    b = Caller(id="canary_b", tenant_id="tenant_b", groups=frozenset(["all"]), roles=frozenset())
    hits = retrieve(CANARY_QUERY_MATCHING_TENANT_A_DOC, b, k=50)
    if any(h == CANARY_DOC_ID_TENANT_A for h in hits):
        page_security_team("CROSS-TENANT LEAK", hits)                # highest-severity alert
    return len(hits) == 0 or CANARY_DOC_ID_TENANT_A not in hits
```

## Pros

- **Structural security**: the model cannot leak what it never received, regardless of prompt injection or model behaviour (08.4).
- **Cheap**: filtered ANN with payload indexes adds milliseconds (04.3.3).
- **Auditable**: every query records the caller and the filter applied (10.4).
- **Multi-tenant SaaS on shared infrastructure** becomes viable.
- Group-based ACLs scale with permission churn without re-indexing.

## Cons

- **Filter selectivity affects recall**: highly selective ACLs need higher `ef`/candidate counts or partitioning (04.3.3).
- **ACL drift**: source permissions change without content changes, requiring a separate sync path (00.1.5).
- **High-cardinality ACLs** (documents shared with thousands of individuals) need group indirection.
- **Every read path must be covered** — search, parent fetch, image serving, citation links, memory, graph traversal. One missed path is a leak.
- Group resolution adds an identity-provider dependency on the request path.

## When to use

Every system with more than one user or more than one permission level. Which is every enterprise system.

## When NOT to use

- Genuinely public single-corpus systems — but still carry `tenant_id` and `visibility`, because scope creeps.
- Never substitute prompt instructions for filtering, at any scale.

## Production at scale

**One filter builder, asserted everywhere.** The single most effective control is that no code path can construct a retrieval query without the ACL filter. Enforce it by making the filter builder the only way to obtain a search client, and unit-test that an unscoped filter raises (08.1).

**Every read is a separate authorisation.** Search is filtered, but parent fetch, page image serving, citation resolution, memory retrieval, graph traversal, and any tool that reads a document each need their own check. Enumerate them and test each.

**Physical isolation for large or regulated tenants**, logical filtering for the long tail — and the mandatory filter in both (00.1.5). Defence in depth against a single bug.

**Continuous cross-tenant canaries** running in production, alerting at the highest severity on any hit. This is the control that catches the bug you didn't think of.

**Permission tests in CI as hard gates** (08.1): fixtures with tenants, users, groups, and documents each caller must *not* see. Run on every retrieval, connector, or index change.

**Non-disclosing refusals**: identical wording and, ideally, similar latency whether a document doesn't exist or the caller can't see it. Otherwise the refusal itself becomes an existence oracle (04.7.5).

**Group cache TTL is a revocation SLA.** A 5-minute cache means revoked access persists for 5 minutes. Set it against your policy and honour explicit revocation events immediately where the IdP supports them.

**Agents act as the caller** (08.5): tools receive the caller object and enforce with it, never a service account that can see everything.

**Log the filter, not just the query**: the audit record should show which principals were used, so a later investigation can prove what the caller was entitled to see (10.4).

## Prod checklist

- [ ] Identity authenticated per request; never taken from request body or model output
- [ ] Groups resolved from the IdP with short-TTL cache and revocation handling
- [ ] Single filter-builder function; unscoped filters raise; enforced as the only path to a search client
- [ ] Filters applied inside the ANN search and the sparse search identically (04.5.1)
- [ ] Every secondary read authorised: parent fetch, page images, citation links, memory, graph, tools
- [ ] Deny-by-default on missing/empty ACL at write and query time
- [ ] Physical isolation for large/regulated tenants plus logical filters everywhere
- [ ] Continuous cross-tenant canaries with highest-severity alerting
- [ ] Permission fixtures in CI as hard gates
- [ ] Non-disclosing refusals for permission-based misses
- [ ] Caller and applied principals recorded in the audit log

## Metrics to watch

| Metric | Why |
|---|---|
| Cross-tenant canary hits (must be 0) | The critical property |
| Authorisation denials by resource type | Coverage of secondary read paths |
| Filtered zero-result rate by tenant size | Over-restriction or ANN recall problems |
| Group-resolution latency and cache hit rate | Request-path dependency |
| Permission-test pass rate in CI | Regression gate |
